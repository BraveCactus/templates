# Написание docstring (Python)

## Когда использовать

- Пользователь просит написать или обновить docstring.
- Добавлена новая функция, класс или модуль без документации.
- Нужно проверить существующие docstring на соответствие формату.
- При рефакторинге, если сигнатура изменилась, а docstring — нет.

## Когда НЕ использовать

- Документация не на Python.
- Пользователь просит комментарии внутри кода, а не docstring.
- Речь о README, CHANGELOG или внешней документации.

## Шаги

1. Прочитай шаблон: `references/template.md`.
2. Определи тип цели:
   - модуль → docstring в начале файла;
   - класс → docstring под `class ...:`;
   - функция/метод → docstring под `def ...:`.
3. Проверь сигнатуру: аннотации типов, `*args`, `**kwargs`, keyword-only.
4. Напиши docstring строго по шаблону.
5. Проверь чек-лист из шаблона.
6. Если менял сигнатуру — обнови docstring, а не только добавь новый.

## Ограничения

- Не дублировать типы в docstring, если есть аннотации в сигнатуре.
- Не добавлять `returns: None` — секция опускается.
- Не менять код функции без явного запроса — только docstring.
- Для приватных функций (`_name`) допускается краткий docstring в одну строку.
- Для `__init__` описывать параметры, но не возвращаемое значение.

## Примеры

### Правильно

```python
def calculate_discount(price: float, percent: int) -> float:
    """Вычисляет цену со скидкой.

    params:
        price: Исходная цена в рублях.
        percent: Размер скидки в процентах (0–100).

    returns:
        Итоговая цена после применения скидки.

    raises:
        ValueError: Если `percent` вне диапазона 0–100.
    """
```
